# 中文职业角色包（销售 / 法务 / 人力）

面向中文场景的职业角色最小集：每包 1 个中文角色（persona.md）+ 2 个中文技能（SKILL.md）。安装后默认停用、不出现在角色选择器，需在设置页核对中文授权摘要并确认后才启用。

## 三包一览

| 包目录 | 角色 id | 角色名 | 技能 | 管什么 | 不管什么（红线） |
|---|---|---|---|---|---|
| `sales/` | zh-sales | 销售数字同事 | zh-sales-lead-brief、zh-sales-followup-draft | 读材料、做《客户背景速览》、出《跟进草稿》；用 sheets 整理客户表 | 不承诺报价与折扣；不决定合同条款；不代发任何消息；不自动外呼 |
| `legal/` | zh-legal | 法务数字同事 | zh-contract-risk-list、zh-legal-doc-checklist | 条款风险提示、《文件核对清单》、期限提醒清单 | 不替代法律意见：不输出「可以签 / 合规」结论；不代拟签署文件终稿；输出固定附「请咨询执业律师」 |
| `hr/` | zh-hr | 人力数字同事 | zh-hr-jd-draft、zh-hr-interview-guide | 《岗位说明（JD）》草稿、面试题纲与评估表草稿、招聘环节清单 | 不做录用决定；不承诺薪酬；不留存简历敏感信息（输出一律占位符）；不输出歧视性筛选条件 |

## 共同红线（每个 persona 正文同步写明）

1. 输出全中文；术语按 `role-packs/terms.txt` 与基表口径（见下节）。
2. 敏感信息一律占位符；示例客户 / 候选人 / 合同全虚构。
3. 最小工具集：销售 `[files, search, todo, sheets]`、法务与人力 `[files, search, todo]`；三包均不含 shell / git，不装 MCP，不绑模型与连接器（`recommended_models` 留空）。
4. 一切外发 / 签署类动作止步于「草稿 + 人工确认」。
5. 包内文档、示例、描述无真实主机名 / IP / 账号 / 密钥。

## 安装动线（本地目录安装）

1. 克隆本仓库到本地。
2. **装技能**：把 `role-packs/<包>/skills/<技能名>/` 整个目录拷入全局技能目录（state_dir 下的 skills/），或项目 `.coworker/skills/`；也可以把技能目录打包成 zip，走设置页技能上传（暂存 → 预览 → 确认）。
3. **装角色**：设置页第三方角色安装入口选「本地目录」，指向 `role-packs/<包>/`，核对中文授权摘要（工具 / 风险 / 默认权限模式）后确认启用。
4. 新建会话选该角色，说一句中文任务（例如对销售角色说「帮我把这份客户材料整理成速览」），验证输出为中文且不越界。

> 说明：包根目录只放 `persona.md` 一个 .md 文件，这是安装机制的硬约束——安装器会把目录里每个 .md 都当角色清单严格解析，多放一个 README.md 就装不上。也因此，git URL 整仓安装形态当前不可用（安装器克隆仓库根后会撞上同样的解析逻辑），请走上面的本地目录动线。

## 术语与质量门（发行前必过）

- `terms.txt` 是领域术语追加表，格式与合并语义见文件头注释（只追加、不覆盖基表；语境分叉走备注区）。
- **发行门**：`python3 scripts/release-gate-role-packs.py`——判据为「quality-gate 自测通过 + 三包全部 .md 术语一致性（基表 + terms.txt 合并）零失败」，任一失败即**未过不可发行**（PRD-183/T3）。
- 误杀可豁免但留痕：在 `terms.txt` 末尾豁免留痕区按行格式登记（文件内 + 当次 PR 描述双重留痕），发行门逐条放行并在输出里打印依据；豁免行残缺或术语不存在则直接失败。
- **常态把关**：`tests/test_release_gate_role_packs.py` 随 CI 的 pytest 执行（失败阻断合并）；`workflows/quality-gate.yml` 的触发路径扩到 `role-packs/**` 为后续一行接入（避开在途 workflow 改动，见 PRD-183/T3 PR 描述）。
- 包版本以本节版本表承载（角色清单格式暂无版本字段，不自造）：
