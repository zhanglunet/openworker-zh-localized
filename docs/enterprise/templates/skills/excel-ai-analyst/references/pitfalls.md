# 踩坑清单详解

SKILL.md 里是一行提醒，这里是"为什么会错、怎么发现、怎么处置"。
**Step 1 读完 MD 觉得表结构不对劲、或 Step 4 出现不匹配时，来这里对号入座。**

---

## 1. 多行表头：`header_rows` 数错一行全废

**现象**：验证通过率 0%，或大量列的值离谱；也可能报「没有任何数据行参与比对」。

**为什么**：中文业务表的表头常见 2~4 行——大标题（"XX公司2025年10月工资表"，跨整行合并）、
分组表头（"应发项目" 横跨 8 列）、字段名、单位行（"元/人"）。脚本把 `header_rows` 之前的
行全部当表头拼列名，之后的全部当数据。多算一行 → 第一条真实数据被吃掉；少算一行 →
"单位行"变成一条数据参与求和。

**怎么发现**：Step 1 的 MD 开头有「表头区逐行解析」和推断出的数据体起始行。
数据预览的第一行应当是一条**真实业务记录**（有工号、有姓名），不是"元"或"小计"。

**处置**：
- 以 MD 里的表头区解析为准，自己数一遍再写进 `header_rows`。
- 拿不准就 `tomd --header-rows N` 强制指定，重跑看预览对不对。

## 2. 合并单元格：表头要铺开，数据区默认不铺

**现象（表头）**：列名缺片段，`基本工资` 匹配不到。
**现象（数据区）**：某个部门的金额是真实值的 3 倍、5 倍。

**为什么**：合并单元格只有左上角那个格有值。表头必须把值铺满覆盖区才能拼出
`应发项目 / 基本工资A` 这样完整的列名；但**数据区如果也铺**，一个跨 5 行的"部门"合并格
会让这 5 行的金额列（如果也参与了铺开）出现重复值，求和直接翻倍。

**处置**：脚本已经做了正确的区分——表头铺、数据区不铺。仅当某个**维度列**（部门、项目）
在数据区合并、导致下面几行分组维度为空时，才用 `"fill_merged": ["DEPT"]` 显式铺开那一列。
**永远不要对金额列用 `fill_merged`。**

## 3. "公式勿动/勿删"列：那是结果不是输入

**现象**：把结果列当输入喂进 `expr`，验证 100% 通过——但你什么都没验证到（拿 G 去验 G）。

**为什么**：中文表常在列名或批注里写"公式勿动""系统自动计算"。这类列是**输出**。

**处置**：
- 结果列一律进 `fields` 并命名为 `X_x`（如 `G_x`），只做 `checks.target`，绝不进 `expr`。
- `expr` 只能引用输入层字段和 `derived` 中间量。
- 自查：如果某个 check 的 `expr` 里出现了另一个 check 的 `target`，重写它。

## 4. check 列 / Countif 列：白送的测试用例

**现象**：忽略它们，等于扔掉原作者留下的单元测试。

**为什么**：原表里常有 `check`、`核对`、`差异`、`Countif` 列，作者用它们自查。
它们的存在说明"这里历史上出过错"，正是最该验证的地方。

**处置**：
- 把 check 列本身加进 `fields`，做一条 `{"expr": "0", "target": "CHK", "tolerance": 0.01}`
  之类的断言（作者的 check 列通常应恒为 0 或恒为 1）。
- 更好的做法是把 check 列背后的逻辑复原成你自己的 `checks` 项，两边都跑。

## 5. `/`、`-`、"不适用"：按 0 算，但业务上不是 0

**现象**：规则 `COEF == 0 and B1 > 0` 同时命中"考核系数真的是 0 分"和"`/` 不参加考核"两类人，
异常清单里混进一堆假阳性。

**为什么**：`fields` 里的非数值单元格一律按 `0.0` 参与运算（否则整行没法算）。
但业务上 `/`（不参加）、`-`（无此项）、空（在职未发生）和真正的 `0` 是四回事。

**处置**：用 `<变量名>__raw` 拿原始字符串区分：

```jsonc
{"name": "不参加考核却发了绩效", "when": "COEF__raw == \"/\" and B1 > 0"}
{"name": "考核 0 分仍发绩效",   "when": "COEF__raw != \"/\" and COEF == 0 and B1 > 0"}
```

Step 2 的「取值陷阱」一节要把每个占位符的含义写清楚，交付时也要告诉用户。

## 6. 汇总行 / 小计行：不排掉金额翻倍

**现象**：合计金额恰好是真实值的 2 倍（表尾一行"合计"）；或分部门汇总里多出"小计"这个部门。

**为什么**：中文表习惯把小计行**混在数据体中间**（每个部门后面跟一行"XX部门小计"），
它们和真实数据长得一样。

**处置**：
- `"skip_when": {"label_in": ["汇总", "合计", "总计", "小计"]}`；Step 1 的 MD 里
  有「疑似汇总/小计行」一节，把实际用词抄过来。
- 词别取太泛：`"总"` 会误伤"总监""总部"。命中规则是**整行任一单元格包含该词**。
- 验证报告里会写"按 label_in 跳过 N 行"，对一下 N 和你数出来的小计行数是否一致。

## 7. 离职 / 中途入职人员：不匹配的高发人群

**现象**：99% 的行都通过，剩下零星几行差额没有规律。

**为什么**：这些人当月按天折算、少发一半社保、或者有一次性补发/扣回，
主表里可能是人工覆盖的值，跨表也可能查不到对应记录。

**处置**：不匹配清单出来后，先按"是不是当月入离职"分一次组。是的话，
在报告里单列一节说明口径，而不是去改 `expr` 迁就它们。
`cross_checks` 的「未匹配键」清单往往和这批人高度重合。

## 8. 浮点误差：逐层 round，比较用容差

**现象**：差额是 0.000000001 或 0.01 这种量级。

**处置**：
- Excel 的每一层小计通常都各自四舍五入到分，所以 `derived` 和 `expr` 要**每层各自
  `round(x, 2)`**，而不是最后统一舍一次。
- 比较永远用 `tolerance`，不要期待 `==`。金额 0.01、比率 0.0001。
- 验证报告会统计"差异非零但在容差内"的条数——这个数很大说明舍入层级建模得不对，值得回头看。

## 9. CSV 编码：一律 `utf-8-sig`

**现象**：用户双击打开 CSV，中文全是乱码，当场对这套流程失去信任。

**处置**：脚本产出的所有 CSV 已经是 `utf-8-sig`。你自己另外写 CSV 时也必须带 BOM。

## 10. 绝不修改用户原表

**现象**：用户发现原表被动过——这是不可逆的信任损失，尤其在工资/成本这类表上。

**处置**：
- `tomd` / `verify` 只读打开原文件；所有产物写到独立输出目录（`01_raw_md/` … `04_output/`）。
- 不要用任何别的手段回写原表，哪怕用户说"直接改就行"——先产出结果表，让用户自己合并。
- 需要重算缓存值（见第 11 条）时，也是**另存一份副本**去转换，不覆盖原文件。

## 11. 公式列显示"全空"：这个 xlsx 没有缓存值

**现象**：MD 里某列「有公式但取值全空」；verify 会打出严重告警——此时**验证结果不可信**
（拿 0 去对撞你的 `expr`，全是假不匹配）。

**为什么**：xlsx 同时存公式和上次计算的缓存值。程序（pandas/openpyxl/导出系统）生成的
文件往往只写公式不写缓存值，Excel 打开时才现算。

**处置**：让用户用 Excel/WPS/LibreOffice 打开另存一次，或：

```
soffice --headless --convert-to xlsx --outdir <输出目录> <原表.xlsx>
```

然后对**转换后的副本**重跑 Step 1 和 Step 4。别在没有缓存值的文件上硬跑验证下结论。

## 12. `.xls` 老格式：先转 `.xlsx`

`openpyxl` 不支持 BIFF 格式的 `.xls`，脚本会直接报错并给出转换命令：

```
soffice --headless --convert-to xlsx <原表.xls>
```

`.xlsm`（带宏）可以直接读，宏不会被执行。

## OpenWorker 环境特有的坑

## 13. 审批弹窗把流程打断

命令白名单是**命令词前缀**匹配，而且**任何包含 `&& ; | > < ` $( (` 或换行的命令一律强制审批**。
所以：一条 `run_shell` 只做一件事，不要串联、不要重定向、不要内联多行脚本（heredoc）。
`spec.json` 用 `write_file` 写文件。
文件名带括号（`工资表(1).xlsx`）也会触发强制审批——必要时先复制成不带括号的名字再处理。

## 14. 技能资源目录不在会话根目录里

`references/*.md` 和 `scripts/excel_ai.py` 装在技能目录下，通常**不在**会话的工作区/草稿目录里，
`read_file` 可能因为"路径超出根目录"被拒。改用 `run_shell` 的 `cat` 读，
或直接 `python3 <resources_path>/scripts/excel_ai.py ...` 执行（执行不受文件工具的根目录限制）。
路径永远取 `load_skill` 返回的 `resources_path`，不要硬编码。

## 15. 找不到用户的表

用户说"就那个工资表"时，先 `list_files` 看工作区和会话草稿目录（默认 `~/OpenWorker/<会话 id>`），
把候选文件名列给用户确认，**不要猜文件名**。多个版本（`v2`、`最终版`、`最终版(1)`）并存是常态，
选错一份，后面所有结论都白做。

## 16. 缺依赖

```
pip3 install pandas openpyxl
```

系统 Python 受保护时加 `--break-system-packages`。装依赖是一条会弹审批的命令，
提前跟用户说明用途（纯本地解析 Excel，无网络上传）。
