## 0. 范围、口径与约束

1. 本设计覆盖中文角色 skill 包装入 Claude Code / Cursor / Codex / Pi 四类工具后的**同步检查项定义**，目标是"装得到、装得对"，并抽查中文触发词"唤得起"。T1 不产出可执行脚本，只产出检查项规范、判定规则与输出格式。
2. **借鉴声明**：本设计仅借鉴 `xingkongliang/skills-manager` 的"同步检查"思路（目录存在性核对、版本比对、残留清理三项检查的组织方式）；该仓库的代码许可协议**未核实**，本项目**不复用其任何代码**，检查项全部按本仓库口径重新定义。
3. 检查框架与 PRD-200（livepowers 同步清单）共用，不重复造框架；共用/差异边界见 §7。
4. 文中所有涉及环境的信息一律使用占位符（`<repo>`、`<用户主目录>`、`<发布批次>`、`<检查人>` 等），不含真实主机名、IP、账号、密钥。本文示例中的 `~` 均为各机器用户主目录的通用写法。
5. 各工具路径与版本标识以 §2 对照表为准；表中"待 T2 实测确认"的条目在 T1 阶段不作为验收依据，仅作为设计预留。

## 1. 对象模型与唯一真源

- **skill 包**：一个自包含目录，目录名即 `skill-id`，内含 `SKILL.md`（含 frontmatter 元数据）及若干附属资源（scripts/templates/assets 等）。
- **发布清单（manifest，唯一真源）**：仓库内每个发布批次一份，路径占位为 `<repo>/manifests/<发布批次>.json`，至少包含以下字段（T1 约定，字段名以 T2 实测后冻结为准）：

| manifest 字段 | 含义 |
| --- | --- |
| `skill_id` | skill 目录名（全局唯一，不含版本号） |
| `expected_version` | 本批次发布版本号（PRD-183 约定的 `X.Y.Z`） |
| `files[]` | 期望文件清单（相对路径 + SHA-256 指纹） |
| `history[]` | 历史版本曾用目录名/别名（供残留检查） |
| `triggers.standard[]` | 标准触发词（与 SKILL.md description 关键词一致） |

- **版本标识优先级（读取已装版本时）**：① `SKILL.md` frontmatter 的 `version:` 字段（PRD-183 约定）→ ② `<skill-id>/VERSION` 文本文件 → ③ 均无则记 `UNKNOWN`。manifest 的 `expected_version` 永远作为比对基准。
- **严重程度分级**（全表通用）：
  - `P0` 阻断：skill 不可用或完全唤不起（必须修复后重测）；
  - `P1` 高：装了但版本/内容漂移，或触发词抽查不达标（功能已受损）；
  - `P2` 中：残留类问题、误触发（不直接损坏功能，但有污染风险）；
  - `P3` 低：提示性问题（缓存未刷新等，重载即消）。

## 2. 各工具安装路径与版本标识对照表

| 工具 | 用户级 skills 根目录（占位写法） | 项目级（如支持） | skill 清单/入口文件 | 已装版本标识载体 | 确认状态 |
| --- | --- | --- | --- | --- | --- |
| Claude Code | `~/.claude/skills/<skill-id>/` | `<repo>/.claude/skills/`（与用户级并存，优先级待确认） | `SKILL.md`（frontmatter：name/description 必备） | frontmatter `version:`（PRD-183 自定义字段，工具是否原样保留**待 T2 实测确认**） | 路径初稿，待 T2 实测确认 |
| Cursor | `~/.cursor/skills/<skill-id>/` | 待 T2 实测确认 | `SKILL.md` | 同上 | 路径与启用条件**待 T2 实测确认** |
| Codex | `~/.codex/skills/<skill-id>/` | 待 T2 实测确认 | `SKILL.md` | 同上 | 路径与启用条件**待 T2 实测确认** |
| Pi | `~/.pi/agent/skills/<skill-id>/` | 无（仅用户级） | `SKILL.md` | 同上 | 路径已在本机验证存在；`version:` 字段读取行为待 T2 实测确认 |

补充约定：

- 若 T2 实测发现某工具不读取 `SKILL.md` frontmatter 的自定义字段，则该工具的版本标识降级为 `VERSION` 文件方案，并在 §4 状态表中把 `version_drift` 记为 `UNREADABLE` 前先触发 FIX-CN-04（见 §3 挂钩表）。
- 四工具通用：`skill-id` 目录名必须与 manifest 一致；目录名**不允许**带版本号后缀（带版本号的目录一律按残留处理，见 CN-SYNC-07）。

## 3. 检查项总表

适用工具未特别注明者为全部四工具；"修复挂钩"为 T4 预留编号与标题，T1 只挂编号不写内容。检查项结果取值统一为 `PASS / FAIL / WARN / SKIP`。

| --- | --- | --- | --- | --- | --- | --- | --- |
| CN-SYNC-01 | Skill 目录存在 | 全部 | 按用户级（必要时含项目级）路径检查 `<skills根>/<skill-id>/` 是否存在且为目录 | 存在且为目录 | 不存在或为文件 = `FAIL` | P0 | FIX-CN-01《安装/重装缺失 skill》 |

## 4. 中文触发词抽查设计

### 4.1 样本构成（每个 skill × 每个工具）

| 样本层 | 条数 | 来源/构成 | 示例形态（以 `<角色skill>` 占位，不指向真实包） |
| --- | --- | --- | --- |
| 标准触发词 | 3 | 取自 manifest `triggers.standard[]`（即 SKILL.md description 中的核心中文关键词，含 skill 中文名本身） | "新媒体文案包"等名词型核心词 |
| 口语变体 A：委托请求式 | 2 | "帮我写个…"、"给我来一份…"、"能不能帮我…"式弱指令 | "帮我写个公众号开头" |
| 口语变体 B：名词/主题式 | 2 | 只报任务名词，无显式动词 | "简历改写" |
| 口语变体 C：角色称呼式 | 2 | 拟人化点名角色 | "让 `HR` 顾问来看看这段" |
| 口语变体 D：场景代入式 | 2 | 描述情境不点名，靠语义关联唤起 | "周五要发推文，一点思路都没有" |
| 反向样本（误触发探测） | 每工具 3 条（跨 skill 共用池） | 指向其他 skill 的变体 + 无关请求 | 指向相邻角色包的口语变体 |

即每个 skill × 工具共 **11 条正向探测**（3 标准 + 8 口语），另每工具共享 3 条反向探测。

### 4.2 抽查方法

1. 在目标工具中开**全新会话**（避免上下文污染），逐条输入探测语句，一条一会话或明确换话题分隔（分隔策略待 T2 实测确认后冻结）。
2. **唤起判定**（满足其一即记命中，观测手段因工具而异，具体 UI/日志观测点待 T2 实测确认）：
   - (a) 工具明确显示加载/调用了该 skill（如列出的 skill 清单、工具调用记录指向该 `SKILL.md`）；
   - (b) 回复内容明显遵循该 skill 的流程或输出模板（结构、栏目、口吻与 `SKILL.md` 规定一致）。
3. 判定容错细则：口语变体中的全角/半角标点、中英混输（如夹杂英文职位词）不构成失败理由，只按语义命中与否判定。
4. 误触发判定：反向样本导致**本 skill** 被唤起，记 1 次误触发。

### 4.3 通过标准

- 标准触发词：3/3 = 100%（任一失败即 CN-SYNC-10 `FAIL`）。
- 口语变体：≥ 6/8（75%）且 A/B/C/D 每类至少 1/2 命中（对应 CN-SYNC-11）。
- 反向样本：0 误触发（对应 CN-SYNC-12）。
- 任一层失败需先走修复挂钩（FIX-CN-10/11/12），修复后**该 skill × 工具的全部 11+3 条重测**，不接受只重测失败条目。

### 4.4 记录格式（probe 级，CSV）

字段：`probe_id, skill_id, tool, variant_type(STANDARD/A/B/C/D/REVERSE), utterance, expected_skill, actual_skill, invoked(Y/N), evidence_note, checked_at, checked_by`

示例行（全部占位）：`PRB-0001, <skill-id>, <tool>, A, "帮我写个<交付物>", <skill-id>, <skill-id>, Y, <观测依据占位>, <时间戳>, <检查人>`

## 5. 检查结果输出格式（skill × 工具状态表）

### 5.1 字段定义

| 字段 | 类型 | 允许值/格式 | 说明 |
| --- | --- | --- | --- |
| `skill_id` | string | 与 manifest 一致 | skill 目录名 |
| `skill_name` | string | 中文名 | PRD-183 定义的中文显示名 |
| `tool` | enum | `claude-code / cursor / codex / pi` | 目标工具 |
| `install_status` | enum | `INSTALLED / PARTIAL / MISSING` | 由 CN-SYNC-01~03 聚合：全过=INSTALLED；01 过但 02/03 失败=PARTIAL；01 失败=MISSING |
| `installed_version` | string | `X.Y.Z` 或 `UNKNOWN` | CN-SYNC-04 读取结果 |
| `expected_version` | string | `X.Y.Z` | manifest 基准 |
| `version_drift` | enum | `NONE / VERSION_DRIFT / CONTENT_DRIFT / UNREADABLE / SKIP` | 分别对应 CN-SYNC-04~06 结果；未装则 `SKIP` |
| `residue` | string | `NONE` 或 `OLD_DIR, ORPHAN_FILES, INDEX_STALE` 的逗号组合 | CN-SYNC-07~09 结果聚合 |
| `trigger_result` | enum | `PASS / PARTIAL / FAIL / SKIP / NOT_TESTED` | CN-SYNC-10~12 聚合；NOT_TESTED 表示本轮未安排抽查 |
| `trigger_detail` | string | 如"标准 3/3；口语 6/8；误触发 0" | 固定摘要格式，probe 级明细另存 §4.4 CSV |
| `conclusion` | enum | `PASS / WARN / FAIL / SKIP` | 聚合规则见 §5.2 |
| `blocking_items` | string | CN-SYNC-ID 逗号列表 | 本行所有 `FAIL` 项 |
| `checked_at` | datetime | ISO 8601 | — |
| `checked_by` | string | 占位 | `<检查人>` |

### 5.2 结论聚合规则

1. `install_status = MISSING` → `conclusion = SKIP`，触发词三检查项全部 `SKIP`（未装无从测）。
2. 存在任一 `P0/P1` 级 `FAIL`（含触发词类不达标）→ `conclusion = FAIL`。
3. 无 `FAIL` 但存在任一 `WARN`（P2/P3 项）→ `conclusion = WARN`。
4. 全部 `PASS` → `conclusion = PASS`；`NOT_TESTED` 的触发词项不阻断 `PASS`，但该行必须在 `trigger_detail` 标注"待抽查"。
5. 状态表每轮检查输出一份（文件名占位 `sync-status-<发布批次>-<日期>.md`），probe CSV 与状态表同行数关系：一个 skill × 工具对应 11~14 条 probe 记录。

## 6. 检查执行流程（T1 规定的顺序与短路规则）

1. **装了没**（CN-SYNC-01→02→03）：01 失败即短路，02/03 及后续全部记 `SKIP`。
2. **对不对**（04→05→06）：04 失败则 05 记 `SKIP`、`version_drift=UNREADABLE`；06 不受 04 影响，仍执行（指纹比对不依赖版本号可读）。
3. **清没清**（07→08→09）：与第 2 步并行可做，不受版本结果影响。
4. **唤得起**（10→11→12）：仅 `install_status ∈ {INSTALLED, PARTIAL}` 时执行；按 skill 全量探测，不做抽测减样。
5. 每轮检查完成后按 §5.2 出结论，`FAIL` 行挂对应 FIX-CN-xx 进 T4 修复队列，修复后整行重测。

## 7. 与 PRD-200 的共用/差异说明

**共用（不重复造框架，直接沿用 PRD-200 的定义）**：

- 三大类检查维度的框架与执行顺序（装了没 / 对不对 / 清没清）；
- 双口径漂移判定：版本号比对（VERSION_DRIFT）+ 内容指纹比对（CONTENT_DRIFT）；
- 严重程度四级分级（P0~P3）与"检查项 → skill × 工具结论"的聚合规则；
- manifest 作为唯一真源的定位、状态表骨架（本设计 §5 是 PRD-200 状态表加列后的超集）、"待 T2 实测确认"标注机制。

**中文包特有（PRD-212 新增，PRD-200 无此维度）**：

- 触发词维度全量：CN-SYNC-10~12 三个检查项、§4 抽查样本库（标准词 + 四类口语变体 + 反向样本）、probe 级记录格式、修复后全量重测规则；
- 中英混输/全角半角容错判定细则；
- 适用工具集合不同：PRD-200 面向 livepowers 英文包的工具集，本设计面向 Claude Code / Cursor / Codex / Pi 四工具（路径表 §2 为本 PRD 专属交付）。

**边界约定**：若 PRD-200 后续修改共用框架（分级、聚合规则、manifest 字段），本 PRD 的检查项定义跟随同步，差异部分（触发词维度）不受影响；反向亦然。
