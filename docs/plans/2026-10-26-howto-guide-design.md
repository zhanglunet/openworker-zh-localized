盘点发现的三处张力（本设计必须处理）：

1. **与 README 重叠**：指南核心路径（安装、启动、故障）和 README §4–§7 大面积重合。若两边都写全，必然双写漂移。本仓构建实录栏目已有「文档层为单一事实源」的惯例，§1 按同一原则分工。
2. **对未合并脚本的依赖**：PR #38 未合并，`install-zh.sh` 的最终接口以合并时为准。指南安装章要能先按 README §5 落地、脚本合并后平滑切换（决策 D5）。
3. **指南落点无先例目录**：仓库没有 `docs/guide/`，既有指南平铺在 `docs/` 根下。211 是多章手册，平铺会和根目录其他文档混杂，需在 T1 定落点（决策 D1）。

## 1. 指南信息架构

### 1.1 落点与文件组织（决策 D1）

新建 `docs/guide/` 目录，一章一文件，编号前缀定序：

| 文件 | 内容 |
|---|---|
| `docs/guide/README.md` | 指南首页：路径图、章节索引、与开箱叙事的分工说明 |
| `docs/guide/01-install.md` | 第 1 章 安装与启动 |
| `docs/guide/02-config.md` | 第 2 章 配置服务商与模型 |
| `docs/guide/03-first-task.md` | 第 3 章 首个任务 |
| `docs/guide/04-scenarios.md` | 第 4 章 常用场景 |
| `docs/guide/05-troubleshooting.md` | 第 5 章 故障排查 |
| `docs/guide/templates/` | 模板库（T3 落地，一模板一文件 + 索引，字段见 §3） |

理由：一章一文件让 T2/T3 可以并行动笔、并行评审；编号前缀保证顺序稳定，跨章引用用相对路径，不依赖标题文字。

### 1.2 章节大纲（每章一句话目标）

| 章 | 一句话目标 | 内容要点 | 素材来源 |
|---|---|---|---|
| 导读（首页） | 30 秒内选对自己的路径 | 三条路径分流（下载 DMG / 一行脚本 / 源码）、全册路径图、与 121 叙事的分工说明 | 新写 |
| 1 安装与启动 | 装好并第一次打开应用 | 三条安装路径各一节，逐步图解；装后自检（版本号打印、导入冒烟） | README §4、§5；PR #38 脚本 |
| 2 配置服务商与模型 | 连上一个可用模型并验证 | 服务商配置模板块、自定义 API 说明、连通性自检 | `docs/config.example.toml`、README §2 |
| 3 首个任务 | 10 分钟内端到端跑通一次真实任务 | 新建会话串、发第一条提示词、看懂工具调用与审批、确认结果 | 新写（T2 实拍） |
| 4 常用场景 | 把日常高频用法变成可照抄的定式 | 每场景一节：收件箱处理、定时任务、技能与角色、连接器接入、上下文面板（链 `docs/context-panel-guide.md`，不复制） | 新写 + 既有指南互链 |
| 5 故障排查 | 按现象自查、自解，不用先去提问 | 现象索引表（现象 → 可能原因 → 对应步骤）；收录白屏、编译缺 CMake、缺 sidecar、多 Python 绑错解释器等已知坑 | README §7、安装实录踩坑段 |
| 附录 A 模板库索引 | 一切可复制模板只有一个入口 | 链 `docs/guide/templates/`，见 §3 | T3 落地 |
| 附录 B 术语表 | 指南用词与产品界面一致 | 只放链接，指向质量门口径，不另抄一份（防双写） | `scripts/quality-gate.py` |

### 1.3 与 PRD-121 开箱叙事的分工边界

| 维度 | PRD-121（故事） | PRD-211（操作手册） |
|---|---|---|
| 回答的问题 | 为什么做、怎么造出来的、踩过什么坑 | 照着做怎么做、做到什么样算对 |
| 形态 | 构建实录栏目文章（目标 / 过程 / 踩坑 / 产物） | 分章手册（步骤块 + 模板块） |
| 时效 | 事件发生时定格，事后不改 | 随版本持续修订，章头标适用版本 |
| 同一事实 | 只讲脉络，不给完整操作步骤 | 给步骤与判据，不讲来历 |

事实源原则：**操作步骤只在手册写全，叙事只引用不复制；命令与配置以脚本和 `docs/config.example.toml` 为准，手册除模板块外不另存一份长命令。** README §4–§7 在 T2 落地时改为「摘要 + 指南入口链接」（本 T1 只定原则，T2 执行），避免三处写同一件事。

## 2. 图解规范

### 2.1 步骤块格式（决策 D2）

每个操作步骤用统一的五要素步骤块，T2 写作一律套用：

```markdown
### 步骤 N：<动作名，一句话，能独立成标题>

- **目的**：<这一步做完得到什么，一句>
- **操作**：
  1. <动作，界面文案用「」引用当前中文文案>
  2. <命令进代码块，可整段复制>
- **预期结果**：<可观察的判据，如窗口出现什么、终端打印什么>
- **图示**：<占位行或实拍图，约定见 §2.2>
- **卡住时**：→ [故障排查对应条目](05-troubleshooting.md#<锚点>)
```

硬性要求：**删掉全部图示，步骤仍可独立执行**——文字是主体，图只作辅助确认（对应 PRD 风险口径「步骤文字为主、截图为辅」）。

### 2.2 图示占位约定（决策 D3，沿用既有惯例并扩展）

沿用 `docs/context-panel-guide.md` 的占位惯例，不另起一套：

- 未实拍时写斜体占位行：`*(示意图：<画面内容描述>，<补图时机>补)*`，例：`*(示意图：首次启动后的主窗口全貌，T2 实拍补)*`。
- 实拍图统一放 `docs/assets/`，命名 `guide-<章号>-<步号>.png`（例 `guide-03-2.png`）。
- 图注必须带适用版本：`图：<描述>（适用 v<版本号>-zh）`。
- 截图脱敏：账号、密钥、真实路径一律打码或换占位值；演示数据用虚构角色与虚构内容（沿用面板指南的红线做法）。

### 2.3 版本防脱节措施

1. **章头版本字段**：每章头部标 `适用版本：v<版本号>-zh` 与 `最后核对：<日期>`，T5 实测后回填。
2. **文案引用可检索**：步骤里引用的界面文案用「」括起，界面文案变更时可按引号内容反查受影响步骤。
3. **上游变更联动**：PRD-068 上游周报若命中界面文案变更，受影响清单默认包含 `docs/guide/`，由当期维护者顺手核对图注版本。
4. **截图只拍稳定界面**：高频变化区域（版本号横幅、活动弹窗）不入截图，用文字描述代替，从源头减少图与版本脱节。
5. **模板失效防线**：模板块带实测状态字段（§3），未实测的模板不进正文步骤，只能留在模板库并标注状态。

## 3. 可复制模板块规范

### 3.1 模板块格式（决策 D4）

正文与模板库中的模板一律三段式：

```markdown
> **模板：<名称>**（编号 TPL-<域>-<序号>）
> 用途：<一句话，什么场景下用>

​```text
<可整段复制的正文，占位符见下>
​```

占位符：`<占位符名>` = <替换成什么、从哪拿>
```

（上例代码围栏前的零宽空格仅为在本文档中展示，实际模板文件不加。）

占位符约定：

- 统一用尖括号加中文说明：`<你的服务商 API 密钥>`、`<项目文件夹路径>`。
- **不用长得像真值的假占位符**（不写 `sk-xxxx` 这类），避免读者把占位符当真值用、或把真值误发出去。
- 模板正文复制后不改任何占位符也应一眼能看出「还没填完」。

### 3.2 模板条目字段

模板库中每个模板一个文件，头部带字段表（与本仓文章模板的「条目带元数据」惯例对齐）：

| 字段 | 说明 |
|---|---|
| 编号 | `TPL-<域>-<序号>`，域枚举：CFG（配置）/ PRM（提示词）/ CHK（自查清单） |
| 名称 | 一句话能懂的名字 |
| 场景 | 什么情况下用，对应指南章节锚点 |
| 模板正文 | 三段式模板块本体 |
| 占位符清单 | 每个占位符的替换说明 |
| 前置条件 | 用之前要先完成什么（链回指南步骤） |
| 实测状态 | `未实测` / `已实测（<日期>，<环境一句话>）`；T3 逐个实测后回填 |
| 关联步骤 | 链回指南正文使用该模板的步骤锚点 |

### 3.3 首批模板候选（给 T3 的输入，不在本 T1 展开正文）

| 编号 | 名称 | 底稿/来源 |
|---|---|---|
| TPL-CFG-01 | 服务商与模型配置 | `docs/config.example.toml` 裁剪 |
| TPL-PRM-01 | 首个任务提示词（读项目并给出摘要） | T2 第 3 章实拍时定稿 |
| TPL-PRM-02 | 定时任务提示词（每日定时汇总） | 第 4 章定时任务节 |
| TPL-PRM-03 | 技能调用提示词 | 第 4 章技能与角色节 |
| TPL-CHK-01 | 装后自查清单 | 第 1 章装后自检 + 第 5 章现象索引 |

## 4. 与 PRD-121 互链方案（T4 的设计输入）

### 4.1 锚点约定

- 章节文件与编号（§1.1）一经发布不改名、不改号；标题可润色，但跨文件链接一律用「相对路径 + 文件」为主、章内锚点为辅，标题改名不致断链。
- 章内步骤锚点用步骤标题（`步骤 N：<动作名>`），T2 写作时保持标题稳定；确需改名，改链随同 PR 一起提交（仓库已有链检 CI 兜底）。

### 4.2 互链点位表

| # | 从 | 到 | 形式 |
|---|---|---|---|
| L1 | `README.md` §4 快速开始顶部 | 指南首页 `docs/guide/README.md` | 一行入口：「照图操作版见图解上手指南」 |
| L2 | 指南第 1 章章末「这条路径是怎么来的」 | 构建实录安装篇 `docs/articles/build-in-public/2026-11-install-one-line.md` | 相关阅读一行 |
| L3 | 构建实录安装篇文末「相关阅读」 | 指南第 1 章 | 回链一行（与 L2 成对，T4 一并落） |
| L4 | 指南第 4 章上下文面板场景节 | `docs/context-panel-guide.md` | 只给入口与一句话，不复制面板指南内容 |
| L5 | 指南首页「先读故事还是先动手」分流块 | 构建实录栏目索引 `docs/articles/build-in-public/README.md` | 分流链接 |
| L6 | 指南第 5 章各现象条目 | 对应叙事篇的踩坑段（有则链） | 「来历」链接，可选 |

原则：手册 → 叙事只放章末相关阅读，不打断操作步骤；叙事 → 手册放文末相关阅读（与栏目既有体例一致）。
