# openworker-zh-localized 企业定制版 playbook 大纲（T1 设计稿）

> PRD-030/T1（trend #181）。本稿为 playbook 的完整大纲：章节划分 + 每章输入/输出/检查清单 +
> 与 `docs/enterprise/` 现有文档的对应关系。T2–T4 按此大纲写各章正文。

## Playbook 总览

目标读者：下一次企业换肤打包的执行人（可能是第一次干这活的人）。
使用方式：按章节顺序走，每章的"检查清单"全勾才能进下一章。

| 章 | 名称 | 对应现有文档（`docs/enterprise/`） |
|---|---|---|
| 1 | 换肤打包 | 换肤打包相关文档 |
| 2 | 三仓同步 | 三仓同步相关文档 |
| 3 | 部署 | 部署相关文档 |

> 注：上表"对应现有文档"列为占位——T1 起草时未逐份打开核对。T2–T4 动笔前必须先盘点
> `docs/enterprise/` 实际文件清单，把"第 X 章 ↔ 具体文件名"一一对应上；
> 若发现现有文档与 openworker-enterprise 现状不一致，先在走查报告里标注，不在本大纲里假设。

## 第 1 章：换肤打包

**输入**：汉化版基线版本（tag）、企业品牌素材包（名称/Logo/文案）。
**输出**：企业版安装包（macOS DMG / Windows 安装器）+ 换肤记录单。

检查清单：
- [ ] 品牌替换五件套齐：应用名、图标、包名、下载站、免责声明（参考 openworker-enterprise README 的既有实践）
- [ ] 换肤后全量 UI 走查一遍，无英文残留、无占位符
- [ ] 安装包在干净机器上装得上、打得开
- [ ] 换肤记录单已填（基线 tag、企业名、打包人、日期）

## 第 2 章：三仓同步

**输入**：第 1 章的换肤记录单（知道基线是哪版）。
**输出**：三仓版本对应表。

三仓：`openworker-zh-localized`（汉化基线）/ `openworker-enterprise`（企业版）/ 上游
（`andrewyng/openworker`，经 `Lenovo202409/openworker-zh` 中转）。

检查清单：
- [ ] 确认企业版基线 = 汉化版某 tag（不是某次随手 commit）
- [ ] 确认汉化版基线与上游的对应关系（参考 PRD-029 的同步报告）
- [ ] 三仓版本对应表已更新（企业版 vX.Y.Z ← 汉化版 tag ← 上游 tag）

## 第 3 章：部署

**输入**：第 1 章的安装包 + 第 2 章的版本对应表。
**输出**：下载站可下载 + 版本留档 + 发布日志已更新。

检查清单：
- [ ] 安装包已上传分发渠道（参考现有 aiworker.download 流程）
- [ ] 下载站版本页可访问、链接有效
- [ ] 版本留档完成（历史版本页可查）
- [ ] 发布日志已更新（changelog/weekly，按现有习惯）
- [ ] 回滚方案就绪（上一个稳定版安装包保留可下载）

## 附：走查要求（T5 用）

- 拿一次真实换肤需求按 1→2→3 章走一遍，记录每个检查清单项的实际耗时与卡点。
- 走查报告必须包含"playbook 修订清单"（至少修订一处，否则视为走查不充分）。
- 若找不到真实换肤需求，降级为桌面推演，但走查报告中必须注明"推演"而非"实战"。
