# PRD-488/T1：中文技能评估设计草稿

> 来源：PRD-488（openworker-zh-localized 中文技能评估），对应 trend issue zhanglunet/trend#2360
> 状态：设计草稿，只开 PR 不合并，等用户 review
> 日期：2026-11-17

## 一、问题

中文技能包越写越多，但没有一套东西定期回答“这些技能还管用吗”：

- 技能会过期（上游变了，技能教的还是旧做法）；
- 技能会重叠（两个技能教同一件事，agent 无所适从）；
- 技能会失效（agent 根本不按技能走，译稿照错不误）。

评审流水线审的是产物，监督回路盯的是 agent 干活的过程，收件箱管的是等人拍板——没有一个地方审“技能本身”。本设计补的就是这一环：给中文技能包做定期体检。

## 二、评估四件套

### 1. 质量门：技能是否真让 agent 少译错

- **判定口径**：质量门只回答一个问题——挂上该技能后，agent 在同一批翻译任务上的译错率是否显著低于不挂技能的对照组。译错按既有评审口径计（术语、数字、句式、风格四类），不另立新口径。
- **阈值（草稿，待 T1 设计评审定、实测后复核）**：
  - 过关：译错率相对对照组下降 ≥ 20%，且四类译错中没有一类恶化超过 5%；
  - 待整改：下降在 0–20% 之间，或某一类恶化超过 5%；
  - 不过关：译错率不降反升，或对照组本身不可复现（样本不足/任务漂移）。
- **判定规则**：同一技能至少跑两轮对照（不同任务批次），两轮结论一致才落账；结论不一致记“待复核”，不直接判不过关。
- **不做的事**：质量门不审译稿本身的好坏（那是 PRD-429 评审流水线的事），只量“有技能 vs 没技能”的行为差。

### 2. 重叠检测：中文技能之间别重复

- **方法**：两层。
  - 语义层：技能正文做向量相似度，相似度 ≥ 0.85 的技能对进候选清单；
  - 规则层：候选对再由人工（或评审规则）判定是“真重复”（教同一件事、同一触发条件）还是“假重复”（表面像、适用场景不同）。
- **判定口径**：只有人工确认的真重复才进整改清单；向量相似度只是筛子，不是判决。
- **处理**：重叠不直接删技能。整改清单里写明合并、拆分或保留并注明的建议，由人工拍板。

### 3. 合成评测集：造中文题考技能

- **题源**：题必须源自真实翻译案例（已发生的译错、评审退回的译稿、术语库争议项），每道题附证据来源（案例编号/链接/截图位置）。无来源的题不进评测集。
- **证据要求**：每道题记录三项——原始译文错在哪、正确译法是什么、对应哪个技能点。缺任何一项的题不入库。
- **规模与更新**：首版评测集不少于 50 道题，覆盖术语、数字、句式、风格四类；每季度从新发生的真实案例里补题，旧题过期（对应技能已改或上游已变）则标记过期、不直接删。
- **防作弊**：评测题不进技能正文、不进训练语料，技能作者不知道具体题目，只知道题型分布。

### 4. 实测：跑真实翻译任务量行为变化

- **方案**：取真实翻译任务（已脱敏），分两组跑——A 组挂待评技能，B 组不挂；其他条件（模型、提示词、任务批次）保持一致。
- **行为变化度量**：主指标是译错率变化（与质量门同一口径）；辅指标是返工率（评审退回比例）与人工审校时长变化。三项同向改善才算“行为真变了”；主指标改善、辅指标恶化时记“待复核”。
- **样本量**：每轮实测不少于 30 个真实任务；少于 30 个时结论只记“样本不足”，不落账为过关。

## 三、评估结果落账

- **评估报告**：每轮评估产出一份报告，落账在仓内固定位置（路径由 T2 定），内容包括：参评技能清单、四件套各自结论、整改清单增量、待复核项。
- **整改清单**：append-only（只追加、不改写历史）。过期/重叠/失效的技能进清单，写明问题、证据、建议处理方式；技能下线另走审批，评估本身绝不直接删技能。
- **闸门（T3 接）**：评估未过关的技能不得进入下游——其产物进不了评审流水线的“可直接过”通道，只能走人工审校。本 T1 只定口径，闸门实现在 T3。

## 四、与已有 PRD 的边界

| PRD | 它管什么 | 本 PRD 不碰什么 |
|---|---|---|
| PRD-429 评审流水线 | 审译稿（产物） | 不审产物，只评技能本身 |
| PRD-383 checklist 失败验证台 | 验发现真假 | 不验发现，只验技能管不管用 |
| PRD-369 收件箱 | 管等人拍板 | 不管拍板流程 |
| PRD-452 监督台 | 人审 agent 干活过程 | 不审过程，只量技能产出 |
| PRD-012/022/034/037 独立验收测试 | 给单个 skill 写三层测试 | 不给单个 skill 写测试，评整个包的健康度 |

一句话：本 PRD 评的是技能包本身的健康度，不评单个技能的测试、不审产物、不审过程。

## 五、红线

- 只借鉴思路，不复用代码（借鉴对象：NVIDIA/SkillEvaluator Apache-2.0、Claude-BugHunter MIT、stitch-skills Apache-2.0，均只借鉴思路）。
- 评估只进整改清单，技能下线另走审批，绝不直接删。
- 评测题必须有真实案例证据来源，无来源的题不进评测集。
- 质量门阈值由 T1 设计评审定，实测后复核，不拍脑袋定死。
- 实现类 PR 只开不合并，等用户 review。
