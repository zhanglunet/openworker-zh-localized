## 5. 试运行发现

### F1：fenced 代码块的术语保护口径不一致（建议修，不阻塞投产）

- 现象：`apply_terms`（全文处理）把 fenced 代码块当保护区，不替换其中术语；但 `self_check_terms`（逐行处理）不识别 fence，会把代码块里合法的英文术语判为"残留未译"，导致流水线 fail-closed 拒绝产出
- 最小复现：` ``` ` 块内 `provider: openrouter` → apply 后仍英文（符合保护意图），self_check 报 `英文术语 'providers?' 残留未译`
- 试运行中首次 dry-run 即被此问题拦下（上游 README 的 ASCII 架构图在 fenced 块内含 agents/models/providers 等词）
- 影响：真实文档的 fenced 块（命令、配置、图表）常含英文术语，会被误拦；fail-closed 方向是安全的，但会增加人工介入
- 建议：`self_check_terms` 改为 fence 感知（跨行跟踪 ``` 状态），或明确文档"fenced 块内术语也须翻译"。修法走正常 PR，不在本试运行改代码

### 其他诚实项

- 翻译质量、token 消耗未验证（无真实网关 key；设计稿 §2 要求 T5 记录 token，留待首次真实运行时补）
