# 构建实录（Build in Public）

> 一天天用 agent 造出来的中文版，过程也给你看。

这是「英文的 AI 桌面助手，中文的打开方式」的实录侧：用 agent 一步步做出 OpenWorker 汉化版的过程，全部记在这里。本栏目是双语技术传播（PRD-102）的第一个连载系列。

## 怎么读这档栏目

- 每篇绑定一次**真实工作流事件**：做成什么、怎么做、踩了什么坑、留下什么产物。事件在仓库 git 历史与 PR 里可查——过程可查，是这档栏目可信的原因。
- 每篇末尾附英文摘要：英文读者先看摘要再决定是否读中文全文（英文入口见 README.en.md）。

## 更新节奏与运行规则

- **基线：至少月更一篇**；有合并事件（发版、新功能、面板 / 打包类里程碑）触发事件加更——不凑数、不补空文。
- **没有背书不发文**：evidence 链接不到本仓库公开 PR / issue 的选题不立项。
- **写不出踩坑的选题不立项**：踩坑段必填且不得为空话，每条按「现象 → 原因 → 解法」写全。

## 与周报的分工

| 维度 | `docs/updates/WEEKLY.md`（周报） | 本栏目（实录） |
|---|---|---|
| 生成方式 | git 历史自动转写，定时刷新 | 人工策划撰写，PR 评审后发布 |
| 粒度 | commit 级流水账 | 一次完整工作流事件（目标 → 过程 → 踩坑 → 产物） |
| 读者动作 | 查「发生了什么」 | 读「怎么做成、我能复用什么」 |
| 互链 | 实录文末链当期周报；周报不加回链（自动生成文件不改） | — |

## 投稿与标签

- **写法**：复制 [TEMPLATE.md](TEMPLATE.md) 改名为 `<发布日期>-<slug>.md`（slug 用 kebab-case），填齐元数据七字段与四段（目标 / 过程 / 踩坑 / 产物），文末发布合规闸五项逐项勾完，随 PR 发布。
- **形态标签枚举**：面板 / 打包 / 上游同步 / 文档 / 工具链；新标签先在本节登记再使用。
- **发布合规闸五项**：敏感信息扫描、未发布安全细节、术语统一（CI 自动跑，失败阻断）、evidence 核对、数据诚实——逐项定义见模板文末。

## 结构与分工（两层结构，文档层为单一事实源）

- 本目录 `docs/articles/build-in-public/` 是栏目正文的**唯一事实源**：改稿先改这里。
- 站内页 `/build-in-public`（T3 可选落地）从本目录**转写**，不双写正文；仓库 README 目录区只放栏目入口链接（T3）。
- 栏目页脚链回英文 README 与 `/updates` 日志页，形成「实录 ↔ 日志」闭环（T4 双语互通）。
